> #### Summary
This project was developed to study the technologies for building APIs, orchestrators, listeners, batch processes and libraries, using the Java language and the Springboot, SpringSecurity, SpringCloud, Springbatch and Spring ApacheCamel frameworks, as well as the resources provided by OpenAPI 3.0.3, Oracle and MySQL databases and data integration with RabbitMQ. 

The studies also implement execution environments based on Docker and Kubernetes running on WSL (Windows Subsystem for Linux) operating systems Linux Ubuntu 22.0.4 and 24.0.4.

The functionalities were based on the processing flows existing in [**Open Finance Brasil Main Page**](https://www.bcb.gov.br/estabilidadefinanceira/openfinance).

> #### Project Structure - Functionality Support
* The functionalities of the components are supported by 
**Oracle and MySQL databases, messaging via RabbitMQ and batch processing.**
</br></br>
  * The Oracle database is the repository for \
    **information on the OFB control domains and the repository for consent requests,
    as well as control of consent resources/permissions.**
  * The MySQL database is the repository for \
    **information on Security/Tokens/Access Authentication control for OFB and also for audit tracking information.**
  * Messaging connects \
    **the activities of all components with the audit log recording processes.**
  * Batch processes \
    **simulate "Consent Approval" and control "Consent Expiration".**
</br></br>
> #### Project Structure - Persistence, Performance and Data Access
* Persistence
  * The transactional data repository is in Oracle and the persistence mechanisms are implemented by Spring Data JPA.
</br></br>
* Data Access and Performance
  * Access to transactional data **uses the Oracle "Materialized Views" object solution** and these "views" are consumed by the Spring Data JPA implementation.
  * Consistency of consent and resource statuses uses the Oracle "Triggers" and "Procedures" object solution.

  >   ### **Regarding Oracle's "Materialized Visions"**
  >>   Oracle "Materialized Views" are objects classified as Data Warehouses (DW), consolidating transactional data and providing already grouped and classified results, allowing for extremely reduced and simple APIs coding.
  >>
  >>   "Materialized Views" also provide high performance to data access because they are objects that are executed directly "in memory" on the Oracle Host/Instance.
  >>
  >>   "Materialized Views" are maintained directly by Oracle Engines in real-time processes that guarantee the current state of transactional data.
