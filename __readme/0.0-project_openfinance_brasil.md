### Apresentação
Este projeto foi desenvolvido para explorar as tecnologias usadas na construção de APIs, orquestradores, mensageria, processos em lote e bibliotecas.

Foi utilizada a linguagem Java e os Frameworks Springboot, SpringSecurity, SpringSessionJdbc, SpringCloud, Springbatch e SpringApacheCamel, bem como os recursos fornecidos pela OpenAPI 3.0.3, bancos de dados Oracle e MySQL e integração de dados com RabbitMQ.

Os estudos também implementam ambientes de execução baseados em Docker e Kubernetes, ambos rodando em Linux Ubuntu versões LTS 22.0.4 e 24.0.4 dentro componente WSL (Windows Subsystem for Linux) do Windows.

As funcionalidades foram baseadas nos fluxos de processamento existentes na [**Página Principal do Open Finance Brasil**](https://www.bcb.gov.br/estabilidadefinanceira/openfinance).

* As funcionalidades dos componentes são suportadas por

  </br></br>

    * Os processos em lote \
      **simulam a “Aprovação de Consentimentos” e controlam a “Expiração do Consentimentos”.**

> #### Estrutura do Projeto - Persistência, Desempenho e Acesso a Dados
* Persistência
    * O repositório de dados transacionais está no Oracle e os mecanismos de persistência são implementados pelo Spring Data JPA.
</br></br>
* Desempenho e Acesso aos Dados
    * O acesso aos dados transacionais utiliza a solução de objetos **“Materialized Views” da Oracle"** e essas **“visualizações”** são consumidas pela implementação Spring Data JPA nos códigos das APIs.
    * A consistência dos status e permissões dos "CONSENTS" e dos "RESOURCES" utilizam as soluções de objetos “Triggers” e “Procedures” da Oracle.
</br></br>
  
  > ### **Sobre as “Materialized Views” da Oracle**
  > As “Materialized Views” da Oracle são objetos classificados como Data Warehouse (DW) e são objetos **views reais** criados e mantidos nos TableSpace do Oracle.
  >
  > Essas "Views" consolidam os dados transacionais e fornecem resultados já agrupados e classificados, permitindo uma codificação de APIs extremamente reduzida e simples.
  >
  > As “Materialized Views” também fornecem alto desempenho para acesso a dados pois são objetos executados diretamente **em memória** do Host/Instance Oracle.
  >
  > As “Materialized Views” são mantidas diretamente pelos **Oracle Engines** em processos executados em real-time, o que garante o estado atual dos dados transacionais.
</br></br>
