### Summary
This project was developed to explore the technologies used in building APIs, orchestrators, messaging, batch processes, and libraries.

The Java language and the Springboot, SpringSecurity, SpringSessionJdbc, SpringCloud, Springbatch, and SpringApacheCamel frameworks were used, as well as the resources provided by OpenAPI 3.0.3, Oracle and MySQL databases, and data integration with RabbitMQ.

The studies also implement execution environments based on Docker and Kubernetes, both running on Linux Ubuntu versions LTS 22.0.4 and 24.0.4 within the WSL (Windows Subsystem for Linux) component of Windows.

The functionalities were based on the existing processing flows on the [**Open Finance Brazil Main Page**](https://www.bcb.gov.br/estabilidadefinanceira/openfinance).
</br></br>

---
> #### Project Scope
* Only four OFB flows were used, specifically the four main ones:
  </br></br>
    * [**Resources**](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17369706/DC+API+-+Recursos)
    * [**Consents**](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17369335/DC+API+-+Consent)
    * [**Customers**](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17370003/DC+API+-+Registration+Data)
    * [**Accounts**](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/pages/17371726/DC+API+-+Accounts)
      </br></br>

* The above resources were built using all existing services on the [**Official OFB Development Documentation Website**](https://openfinancebrasil.atlassian.net/wiki/spaces/OF/overview).
  </br></br>

* The solution presented in the “OFB Project” has components for:
  </br></br>
    * **Cloud**
    * **Security**
    * **Participant Directory simulation**
    * **Orchestration**
    * **Backend APIs**
    * **Auditing**
    * **Listeners**
    * **and Batches**

      > **Notes:**
      >> “The Participant Directory is a centralized platform that registers participating organizations in the real Open Finance Brazil environment.”*
      >
      > * **About the “Security” features used** \
          The Financial-grade API (FAPI) features of the OpenID Foundation, OAuth 2.0, and OpenID Connect (OIDC) existing in the real OFB environment were simulated
          by the features available in SpringSecurity together with the **SpringSessionJDBC** add-on.
      > * **About the “Participant Directory simulation” functions used** \
          The definitions of the “Participant Directory” existing in the real OFB were simulated in the development of this Project by the SpringSecurity features together with the **SpringSessionJDBC** add-on.
          </br></br>
          The **SpringSessionJDC** add-on provides a complete data model for controlling Clients (participants)
          with registration of Participants, Authorization Grant Types, Roles, and Scopes.
          </br></br>

> #### Project Structure - Functionality Support
* Component functionality is supported by
  **Oracle and MySQL databases, RabbitMQ messaging, and batch processing.**
  </br></br>
    * The Oracle database is the repository for
      **information about OFB control domains and the repository for consent requests,
      as well as the control of consent resources/permissions.**
    * The MySQL database is the repository for
      **information about security control/tokens/access authentication for OFB and also for audit tracking information.**
    * Messaging connects
      **the activities of all components with the processes being recorded in audit logs.**
    * Batch processes simulate “Consent Approval” and control “Consent Expiration.”
      </br></br>

---
> #### Project Structure - Persistence, Performance, and Data Access
* Persistence
    * The transactional data repository is in Oracle, and the persistence mechanisms are implemented by Spring Data JPA.
      </br></br>
* Performance and Data Access
    * Access to transactional data uses Oracle's **“Materialized Views”** object solution, and these **“views”** are consumed by the Spring Data JPA implementation in the API codes.
* The consistency of the statuses and permissions of “CONSENTS” and ‘RESOURCES’ uses “Trigger” object solutions.
